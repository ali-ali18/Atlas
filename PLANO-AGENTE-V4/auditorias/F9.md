# Auditoria da F9: capacidades do motor antigo no v4

09 a 12/11/2026. Branch `ccr-b75b9244-ih1osu`, base `7b6a56f4` (F8 mergeada). Issue-mãe #170.

**Como foi feita.** Auditores independentes Sonnet, só leitura, com o pedido da fase e o diff, usando a skill de segurança da Cloudflare (`cloudflare/security-audit-skill`) em modo guia e trazendo também as dúvidas. A rodada 1 foi validada por uma leitura Opus com provas locais. A rodada 2 foi validada pelo próprio agente de correção (Sonnet): cada achado só foi corrigido depois de um teste que falhava no código da época; o orquestrador revisou o diff das correções graves (cofre e token do GitHub). Decisão do dono (orçamento): tudo em Sonnet na rodada 2.

| S3 | média-baixa | Marcador nu era tratado como JSON e o valor saía escapado. | Só é JSON se `JSON.parse` aceita. |

| S5 | média | Resposta de outro bot (ou webhook) no histórico não marcava o run como contaminado. | `kind:"data"` no histórico marca `untrustedReadInRun`. |
| S6 | baixa-média | Redação só do valor literal. | Variantes URL, JSON, base64 e base64url. |
| S7, S9 | baixa | Auditoria do cofre sem bot e conversa; `secret_request` confundia login com segredo. | Corrigidos. |
| S11, S12, S13 | baixa | `github_compare` aceitava `..` em refs; branch padrão inventado; texto prometia cartão que o v4 não mostra. | Refs validadas, `null` quando desconhecido, erro honesto em inglês. |

## Rodada 2 (`357b9bca..3692e821`): cofre com campos, rotinas parte 2, GitHub escrita, PR e CI, subagentes, vídeo, anexos, habilidades
19 itens (C1 a C10, D1 a D9). Todos os tratados reproduziram.
| ID | Sev. | Cenário | Correção |
|---|---|---|---|
| C1 | alta | Campo secreto com chave diferente de `password` podia ser digitado em input de texto e o valor voltava na leitura da página. | Todo campo `secret:true` só entra em `input[type=password]`; o campo digitado é marcado (`data-atlas-vault`) e nenhuma leitura devolve o valor, mesmo se o site trocar o `type`. Chromium real. |
| C2 | média | Rotina com permissão de login podia ter instrução, gatilho ou painel trocados sem cartão, mantendo a permissão. | Trocar qualquer um apaga a permissão; conceder exige id ou nome exato; o cartão mostra rotina, gatilho e instrução. |
| C3 (parte), C4 | média | Criar ou editar rotina depois de leitura não confiável sem cartão; cron inválido era dado como "criada". | `confirm: when_untrusted`; cron validado de verdade (piso de 5 min que o produto já tinha); falha do agendador é dita. |
| C5 | média-baixa | Pedido de login adotava item sem site pelo nome; escolha ambígua entre logins do mesmo site. | Só itens do mesmo site; ambiguidade exige o nome. |
| D1, D2 | média | Token do GitHub no ambiente de jobs que rodam hooks e config do repositório; push para o `origin` gravado no repo. | Token só nos jobs de rede, com hooks, fsmonitor e helper do repo desligados; push e fetch para a URL do repo da sessão. | D3, D4 | média, baixa | `.env` commitado pelo shell ia ao GitHub; caminho com acento escapava; lista curta; ref começando com `-`. | Lista ampliada, `quotePath` desligado, `code_push` confere os commits a enviar e recusa; workflows e hooks são recusados; ref com `-` inicial recusada. |
| D5 | média | O yt-dlp da VM saía sem passar pelo proxy de saída guardado. | `--proxy` do proxy guardado (também no legado). |
| C7, D7 | baixa | Instrução do cofre mandava usar `{{secret}}` em rotina; cartão do `skill_save` só com o nome. | Texto corrigido; trecho do corpo no cartão. |
